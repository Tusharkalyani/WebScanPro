Architecture Overview

Core Design

WebScanPro is an automated Dynamic Application Security Testing (DAST) suite engineered to inspect authorized web applications and APIs for critical security weaknesses. It operates via modular, safe heuristic analysis without using destructive payloads, denial of service attacks, or unauthorized data exfiltration.

Security Testing Module Detection Technique OWASP Top 10 Mapping Safety Guarantee
Target Crawler Breadth-First link and form extraction with canonical URL deduplication. Reconnaissance Bounded depth & request budgets; ignores media assets & logout links.
Security Headers & Cookies Direct inspection of HTTP response headers and Set-Cookie attribute flags. A05:2021 Security Misconfig Passive inspection. Zero impact on target state.
SQL Injection Analyzer Controlled single/double quote syntax checks and balanced differential analysis. A03:2021 Injection (CWE-89) Non-destructive. Detects database engine syntax errors. Never extracts database contents.
Reflected Input / XSS Injection of unique benign alphanumeric canary tokens (e.g. wsp_chk_<tag>). A03:2021 Injection (CWE-79) Harmless markers. Never executes active script code or alters client cookies.
Authentication & Session Auditor Audits HTTP credential transport, token entropy, and logout invalidation. A07:2021 Auth Failures Tests only designated test accounts. No brute force or credential stuffing.
Access Control & IDOR Analyzer Controlled two-account differential authorization testing and unauth object access. A01:2021 Broken Access Control Operates strictly between designated test accounts A and B. No third-party data accessed.

Safe Testing Methodology & Principles

Authorized Targets Only

WebScanPro restricts scans by default to localhost, 127.0.0.1, and approved private test environments. Operators must explicitly verify ownership or written permission before initializing an assessment.

Polite Rate Limiting

Requests are throttled with configurable delays (default 50ms) and capped with strict page budgets to avoid overwhelming lab applications or exhausting system resources.

Data Privacy & Masking

Sensitive authentication headers, tokens, and personal records are never logged in plaintext or exposed unmasked in executive reports.

Manual Verification Protocol

Automated scanners identify potential weaknesses and indicators. Every finding includes reproduction steps for human security analysts to safely verify the issue before production fix deployment.

Local Security Lab Setup Guide

1. WebScanPro Built-in Mock Target Lab (Zero Dependencies)

Available directly within this application at http://127.0.0.1:5001/mock-lab/. Contains safe simulated endpoints for SQL syntax error detection, reflected XSS, missing headers, cookie security, and IDOR testing without requiring Docker!

2. OWASP Juice Shop (Port 3000)

docker run -d --name juice-shop -p 3000:3000 bkimminich/juice-shop
Once running, browse to http://localhost:3000 or launch a scan against it directly from WebScanPro.

3. Damn Vulnerable Web App (DVWA - Port 4280)

docker run -d --name dvwa -p 4280:80 vulnerables/web-dvwa
Navigate to http://127.0.0.1:4280/setup.php to initialize the database (default credentials: admin / password).
